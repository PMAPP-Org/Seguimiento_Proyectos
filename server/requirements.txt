# ADR-007: adjuntos en object storage S3-compatible (Cloudflare R2), con
# subida directa por URL prefirmada (Paso 17).
#
# **Por qué una dependencia y no SigV4 a mano.** Firmar una URL es un
# algoritmo de una página, pero su resultado es un hash: o coincide byte a
# byte o el store responde `403`, sin decir por qué. Una implementación propia
# —sin un R2 real contra el que contrastarla— solo se podría verificar con
# vectores de prueba transcritos a mano, y cualquier detalle mal recordado
# (orden de las cabeceras canónicas, `UNSIGNED-PAYLOAD`, escapado del path)
# daría un backend que **pasa en local y falla en producción**. `boto3` es el
# cliente canónico de la API S3, R2 lo documenta como el recomendado, y
# —decisivo para este proyecto— **firma sin red**: `generate_presigned_url` es
# cálculo local, así que los tests de `S3BlobStore` corren offline de verdad
# (ver visitacampo/attachments/s3.py).
#
# Se ancla solo `boto3`: `botocore`, `jmespath` y `s3transfer` llegan como
# dependencias suyas y las resuelve pip con las versiones que boto3 declara.
boto3==1.43.63

# Hallazgo Importante de la revisión final de despliegue del demo: nada
# servía `/static/*` (CSS/JS de Django Admin) en producción -- `collectstatic`
# corre en `entrypoint.sh` (Tarea 2) y `config/settings/prod.py` configura
# `STATIC_ROOT`/`STORAGES`, pero sin whitenoise ni un `file_server` de Caddy
# esos archivos no tienen quién los sirva detrás de gunicorn. Se elige
# whitenoise en vez de añadir un `file_server`/volumen compartido en
# `infra/Caddyfile` (la otra opción estándar): sirve los estáticos desde el
# propio proceso de Django sin tocar la infraestructura de Caddy ni añadir un
# volumen nuevo que sincronizar entre `api` y `caddy` (patrón recomendado por
# la propia documentación de whitenoise para despliegues de un solo proceso
# como este, ADR-006: sin Redis/Celery, sin componentes adicionales).
# Versión verificada contra el índice de PyPI en este entorno (6.12.0 es la
# última estable a la fecha) -- confirmar de todas formas contra PyPI antes
# de desplegar, mismo criterio que el resto de versiones ancladas nuevas de
# este plan (ver plans/visitacampo-despliegue-demo-implementacion.md, Global
# Constraints, punto 4).
whitenoise==6.12.0
